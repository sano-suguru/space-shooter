# 弾丸システム最終実機テストガイド

## 概要

弾丸システム統合プロジェクト（Phase 1-4）の最終検証として、実機環境での包括的なテストを実施するための詳細手順書です。

## テスト環境要件

### 推奨システム仕様
- **CPU**: Intel Core i5-8400 / AMD Ryzen 5 2600 以上
- **メモリ**: 8GB RAM以上
- **GPU**: 統合グラフィックス以上
- **ブラウザ**: Chrome 90+, Firefox 88+, Safari 14+, Edge 90+

### 開発環境
- **Node.js**: v18.0.0以上
- **npm/pnpm**: 最新版
- **TypeScript**: v5.0.0以上

## テスト実行手順

### 1. 環境セットアップ

```bash
# 1. 依存関係のインストール
pnpm install

# 2. TypeScriptコンパイル確認
pnpm run build

# 3. ESLint検証
pnpm run lint

# 4. テストスイート実行
pnpm run test
```

### 2. 基本機能テスト

#### 2.1 弾丸生成テスト

**目的**: 全弾丸タイプの正常生成確認

**手順**:
1. ゲームを起動
2. プレイヤー弾丸の発射確認
3. 各種特殊弾丸の生成確認
4. ボス弾丸の生成確認

**確認項目**:
- [ ] プレイヤー弾丸が正常に発射される
- [ ] 爆発弾丸が着弾時に爆発エフェクトを生成
- [ ] ホーミング弾丸がプレイヤーを追尾
- [ ] 反射弾丸が画面端で反射
- [ ] 分裂弾丸が指定時間後に分裂
- [ ] ボス弾丸が複雑なパターンで発射

**期待結果**: 全弾丸タイプが仕様通りに動作

#### 2.2 衝突判定テスト

**目的**: 統合衝突判定システムの正確性確認

**手順**:
1. プレイヤー弾丸と敵の衝突確認
2. 敵弾丸とプレイヤーの衝突確認
3. 貫通弾丸の動作確認
4. 爆発弾丸の範囲ダメージ確認

**確認項目**:
- [ ] プレイヤー弾丸が敵に命中時、敵が破壊される
- [ ] 敵弾丸がプレイヤーに命中時、ダメージを受ける
- [ ] 貫通弾丸が複数の敵を貫通
- [ ] 爆発弾丸が範囲内の敵にダメージ
- [ ] 衝突判定が正確（誤判定なし）

**期待結果**: 全衝突パターンが正常に処理される

#### 2.3 エンチャント効果テスト

**目的**: 16個のエンチャント効果メソッドの動作確認

**手順**:
1. 各エンチャント効果を持つ弾丸を生成
2. 効果の発動確認
3. 効果の持続時間確認
4. 複合効果の確認

**確認項目**:
- [ ] `isPiercing()`: 貫通効果が正常動作
- [ ] `isExplosive()`: 爆発効果が正常動作
- [ ] `isHoming()`: 追尾効果が正常動作
- [ ] `hasChainLightning()`: 連鎖効果が正常動作
- [ ] `canSplit()`: 分裂効果が正常動作
- [ ] `canRicochet()`: 反射効果が正常動作
- [ ] `getCriticalChance()`: クリティカル確率が適用
- [ ] `hasFreezeEffect()`: 凍結効果が正常動作
- [ ] その他8個のエンチャント効果が正常動作

**期待結果**: 全エンチャント効果が仕様通りに動作

### 3. パフォーマンステスト

#### 3.1 フレームレート安定性テスト

**目的**: 60FPS維持の確認

**手順**:
1. ブラウザの開発者ツールを開く
2. Performance タブを選択
3. 以下のシナリオを実行しながら記録:

**テストシナリオ**:

**シナリオ A: 通常プレイ**
- 敵数: 10-20体
- 弾丸数: 50-100個
- 実行時間: 60秒

**シナリオ B: 高負荷プレイ**
- 敵数: 50-100体
- 弾丸数: 200-500個
- 実行時間: 30秒

**シナリオ C: 極限テスト**
- 敵数: 100体以上
- 弾丸数: 1000個以上
- 実行時間: 10秒

**確認項目**:
- [ ] シナリオA: 平均60FPS以上維持
- [ ] シナリオB: 平均45FPS以上維持
- [ ] シナリオC: 平均30FPS以上維持
- [ ] フレームドロップが5秒以上継続しない
- [ ] メモリ使用量が安定している

**期待結果**: 各シナリオで目標FPSを維持

#### 3.2 メモリ使用量テスト

**目的**: メモリ効率とリーク防止の確認

**手順**:
1. ブラウザの開発者ツール → Memory タブ

3. 10分間の連続プレイを実行
4. 定期的にメモリスナップショットを取得

**確認項目**:
- [ ] メモリ使用量が初期値の150%以内に収まる
- [ ] メモリリークが発生しない
- [ ] ガベージコレクションが正常に動作

**期待結果**: メモリ使用量20%削減目標を達成

#### 3.3 CPU使用率テスト

## トラブルシューティング

### よくある問題と解決方法

#### 問題1: フレームレートが低下する

**症状**: ゲームプレイ中にFPSが30以下に低下

**原因と解決方法**:
1. **大量オブジェクト生成**
   - 解決: オブジェクトプールの設定を調整
   - コード: `bulletManager.optimizeMemory()`

2. **メモリリーク**
   - 解決: 非アクティブオブジェクトの削除
   - コード: `gameObjectManager.cleanup()`

3. **衝突判定の負荷**
   - 解決: SpatialHashの設定調整
   - コード: `collisionSystem.optimizeGrid()`

#### 問題2: メモリ使用量が増加し続ける

**症状**: プレイ時間に比例してメモリ使用量が増加

**解決方法**:
1. 弾丸の適切な削除確認
2. イベントリスナーの削除確認
3. オブジェクトプールの動作確認

#### 問題3: 弾丸が正常に動作しない

**症状**: 特定の弾丸タイプが期待通りに動作しない

**デバッグ手順**:
1. ブラウザコンソールでエラー確認
2. `BulletFactory.validateBullet()`で妥当性確認
3. 弾丸の状態をログ出力で確認
